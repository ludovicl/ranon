// the problem

The best AI models are American. Your customer data is under GDPR.

AI agents are most useful on real data: a production database, Stripe, Notion, Slack, support tickets. Today every line they read goes to the model provider, outside the EU, with your customers' names in it. Banning AI costs your teams their best tool. Allowing it without control is the risk your DPO will flag. ranon takes the personal data out of what the model sees, so you can say yes.

Personal data stays in your company

Names, emails, phone numbers, IBANs and addresses become tokens like PERSON_d86896 on the machine. The table that links them to real values never leaves it.

Your teams keep the best models

No need to fall back on a weaker model to stay on the safe side. The agent still counts, joins and debugs on real data: the same value always gets the same token.

Open code your DPO can check

The code and the masking rules are public. Nothing is sent anywhere: no account, no server, no telemetry. If masking fails, the output is hidden rather than sent.

// three promises

Built to fail on the safe side.

A privacy filter that leaks when it breaks is worse than none. ranon is designed around three rules that the test suite enforces.

Fails closed

If masking cannot run (bad state, invalid rules, a crash), the output is hidden. It is never passed through raw.

Stays on your machine

The token map, its secret salt and the name hashes live in a private local directory. No server, no account, no telemetry.

Writes back what it masked

In Claude Code, when the agent posts to Notion or Slack, tokens become real values again just before the call, and you approve it.

// how it works

One small binary, three ways to plug it in.

Inspired by rtk: ranon works as an agent hook, a command proxy or a plain stdin filter. Every output then goes through five passes, from the most structured to the least.

Every psql format. Masked by column name; ambiguous rows are hidden, not guessed.

3

Emails, IBANs, card numbers, phones, public IP addresses and JWTs, anywhere.

// limits

A filter, not a security boundary.

  • It masks results, not queries: a name you type in a where clause is seen by the model.
  • Aliases and computed columns (select email as e, first_name || ' ' || last_name) go through: select columns under their own names.
  • In free text, addresses, birth dates, lone or lowercase names go through: only full names from your users table are recognized.
  • Pseudonyms hide values, not records: ids, cities, amounts and dates stay readable, and together they can single a person out.
  • The agent runs as you, so it could read the token map. Real isolation needs a separate user or a sandbox.
Use it as a seatbelt. ranon catches the personal data that routine queries spill into the agent's context. For hard guarantees, give the agent a database role that can only read pseudonymized views. Everything that gets past is listed in the limits doc.

// install & forget

Two commands, then restart your agent.

macOS or Linux. On Windows, the Linux build should work under WSL if your agent runs there too (untested); ask us if you need native Windows. Install, then run the line for your agent. -g sets it up for all your projects, --dry-run shows what changes before writing it, --uninstall removes it.

~
$ brew install ludovicl/tap/ranon   # or cargo install ranon
# then the line for your agent:
$ ranon init -g                    # Claude Code
$ ranon init -g --agent opencode   # OpenCode
$ ranon init -g --agent codex      # Codex
$ ranon init -g --agent cursor     # Cursor
$ ranon doctor                     # checks that masking is in place
